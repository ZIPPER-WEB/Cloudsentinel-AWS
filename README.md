# CloudSentinel

### AWS Network Security & Diagnostics Platform

CloudSentinel is a **read-only AWS network inventory and configuration analysis tool** built with Python, Boto3, and Streamlit. It gathers networking resources from an AWS account, highlights selected security and routing issues, and presents the results in a local dashboard or timestamped reports.

> **Scope:** CloudSentinel performs configuration checks, not active penetration testing or end-to-end network reachability verification. A finding indicates something to review; it does not prove that a resource is publicly reachable or vulnerable.

## Features

**AWS inventory**
- VPCs and subnets
- Route tables and routes
- Security groups and inbound/outbound rules
- Network ACLs
- EC2 instances and elastic network interfaces
- Internet gateways and VPC peering connections

**Configuration analysis**
- Globally scoped inbound SSH (TCP/22) and RDP (TCP/3389) rules
- Globally scoped all-protocol inbound rules
- Routes in a `blackhole` state
- Non-active VPC peering states, including pending acceptance
- Consolidated findings with severity summaries

**Interfaces and reports**
- Local Streamlit dashboard with a **Scan AWS** button
- Inventory counts, expandable resource tables, and findings table
- JSON and HTML reports generated by the CLI scanner
- Automated tests with pytest

## Architecture

```text
                       AWS Account (selected region)
                                   |
                            Boto3 read APIs
                                   |
                           Resource Collectors
                (VPC, Subnet, Routes, SG, NACL, EC2,
                  ENI, IGW, VPC Peering)
                                   |
                            Network Analyzers
                         (SG, Routes, Peering)
                                   |
                             Findings Engine
                            (combine + summarize)
                                   |
                    +--------------+--------------+
                    |                             |
                app.py                        scanner.py
               CLI workflow                  run_scan()
                    |                             |
              JSON / HTML                    dashboard.py
                reports                      Streamlit UI
```

The CLI and dashboard currently invoke the existing collectors and analyzers through **separate entry points**. The dashboard does not automatically generate report files; run the CLI for JSON/HTML exports.

## Requirements

- Python 3.10+
- AWS CLI configured locally
- An AWS identity with permissions to read the resources being inspected
- Network access to the relevant AWS APIs

The current source uses the AWS CLI profile **`netdoctor`** and region **`ap-south-1`**. These are configured in `app.py` and `scanner.py`; update both files if you use a different profile or region.

### AWS permissions

Use a dedicated **least-privilege, read-only** IAM identity. The application uses AWS STS `GetCallerIdentity` and EC2/VPC describe APIs. Verify the exact permissions required by each collector for your environment. Never provide write access just to run the analyzer.

## Getting Started (Windows PowerShell)

### 1. Clone your repository

Once you have published it to GitHub:

```powershell
git clone <YOUR_REPOSITORY_URL>
cd cloudsentinel-aws
```

If working in your existing `netdoctor-aws` folder, open that folder instead.

### 2. Create a virtual environment

```powershell
python -m venv .venv
```

### 3. Install dependencies

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Ensure `requirements.txt` includes the dependencies used by the project, including `boto3`, `streamlit`, `pandas`, and `pytest`.

### 4. Configure AWS locally

```powershell
aws configure --profile netdoctor
```

Set the region to `ap-south-1`, or update the region in the source files. Credentials stay in your local AWS configuration; **never add them to the repository**.

### 5. Run the CLI scan

```powershell
.\.venv\Scripts\python.exe app.py
```

This prints inventory and findings to the terminal and generates timestamped JSON and HTML reports in `reports/`.

### 6. Launch the dashboard

```powershell
.\.venv\Scripts\python.exe -m streamlit run dashboard.py
```

Open the local address printed by Streamlit (typically `http://localhost:8501`) and click **Scan AWS** in the sidebar.

### 7. Run tests

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

At the time of preparation, the project owner reported **10 passing tests**. Rerun the suite after making changes.

## What the Findings Mean

| Check | Example result | Interpretation |
|---|---|---|
| SSH rule open to `0.0.0.0/0` or `::/0` | HIGH | Review globally scoped inbound TCP/22 permissions. |
| RDP rule open to `0.0.0.0/0` or `::/0` | HIGH | Review globally scoped inbound TCP/3389 permissions. |
| All protocols allowed from anywhere | HIGH | Review broad inbound protocol access. |
| Route state is `blackhole` | HIGH | Route target may be unavailable or invalid. |
| Peering awaiting acceptance | LOW | Request may be legitimate but is not active yet. |
| Other non-active peering status | MEDIUM | Inspect status and intended connectivity. |

Severity labels are **project-defined heuristics**, not AWS Security Hub ratings. A security group rule alone does not establish public reachability; assess attachments, routing, public addressing, NACLs, and other controls separately. The analyzer does not yet model complete packet paths.

## Security and Privacy

- Designed to call read-only AWS APIs; do not grant modification permissions.
- Do not commit AWS credentials, `.aws/` files, environment secrets, or `.venv/`.
- Generated reports and screenshots may expose account identifiers, resource IDs, IP addresses, and configuration details. Review/redact before sharing.
- Do not publish live scan data from an account you do not have permission to disclose.

Recommended `.gitignore` entries:

```gitignore
.venv/
__pycache__/
.pytest_cache/
*.py[cod]
.env
.env.*
.aws/
reports/*.json
reports/*.html
```
